# Release v1.0.2 — Design

Date: 2026-10-22
Status: approved for implementation
Baseline: master @ `62d8746` (CI 11/11 green, valgrind hard gate, Performance green)

## 1. Objective

Ship v1.0.2: finalize the CHANGELOG `[Unreleased]` section, align README
assertion counts with measured reality, add the release entry, and tag —
using the repo's own `tools/tag-release.sh` for version consistency.

Scope (user-confirmed): standard release — changelog finalize, README
count sync, migration-doc version line (via script), annotated tag.
**Zero code changes**: `src/` and `include/` must have a zero-line diff
across the entire release; 1.0.2 is a test/CI/documentation release, so
the patch bump is semantically correct and `docs/migration.md` needs no
new migration section (the script updates its version-number example
lines mechanically).

Non-goals: no GitHub Release page (tag push triggers the workflows; a
`gh release create` can be added later if wanted); no deletion of a
pushed tag under any circumstances; no code or build-system changes.

## 4. Release flow (tools/tag-release.sh)

1. Measure counts (already done, recorded in §2; re-verify at execution
   time — the plan includes a verification step before each doc commit).
2. Hand-edit CHANGELOG (§2) → commit
   `docs(changelog): 📝 finalize 1.0.2 release notes`.
3. Hand-edit README (§3) → commit
   `docs(readme): 📝 sync assertion counts with 1.0.2 suites`.
4. `ctest` 8/8 discipline check.
5. `tools/tag-release.sh --dry-run 1.0.2` → review the printed action
   list: CHANGELOG date, migration.md version lines, CMakeLists
   VERSION 1.0.1→1.0.2, reconfiguration of every `build_*/` tree.
6. `tools/tag-release.sh 1.0.2` — the script's guards (master branch,
   clean tree, tag absent, version strictly greater) all hold; it
   commits the bump and creates annotated tag `v1.0.2`. Verify with
   `git show v1.0.2`.
7. `git push && git push --tags` (the script never pushes).
8. Post-push verification: both workflows green on the tag commit
   (`gh run watch --exit-status` on the new CI and Performance run
   IDs); `git tag -l v1.0.2` present; `gh run list --limit 2` both
   success.

## 5. Risks / Mitigations

| Risk | Mitigation |
|---|---|
| Script bail-out (dirty tree, wrong branch, existing tag) | Pre-check before dry-run; dry-run prints all bail conditions |
| Script's auto-commit colliding with manual commits | Manual doc commits land first; the script only touches its four declared targets |
| ctx_smoke count drift vs README | Measured 200014 matches; README keeps `~` prefix |
| Format gate red on tag commit | Doc-only changes; clang-format dual-version gate re-verified before push |
| `build_*/` reconfiguration failure inside script | Script aborts with `set -euo pipefail`; re-run after fixing |
| Post-push defect discovered | Never delete a pushed tag; ship 1.0.3 instead |

## 6. Spec self-review

- No placeholders: every count is measured (§2, §3); the release date is
  fixed (2026-10-22).
- Consistency: §2's Changed bullet and §3's table use the same measured

- Scope: two doc files + scripted tag — single-plan size.
- Ambiguity: "README preamble claims" is bounded to total-count/suite
